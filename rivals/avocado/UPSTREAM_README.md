# 005 — Retrained Avocado as a bridge between Dataset 2 and Dataset 3

*(Started 2026-07-29. Re-run with `bash runall.sh`. Results and conclusions in `notebook.md`.)*

## Question

CANDI consumes raw read counts, so it can only be trained on **Dataset 2** (ENCODE's
present-day processing of the EIC experiments, originally Mehdi's `DATA_CANDI_EIC` on Fir).
The published EIC leaderboard lives in **Dataset 3** (the −log10 p-value tracks the challenge
itself distributed, Synapse `syn17083203`). Avocado needs only signal tracks, so it can be
trained on *either* — which makes it the one method that can measure the translation between
the two evaluation spaces directly.

> **This experiment runs on Nibi, not Fir.** It was written for Fir and moved on 2026-07-30,
> after two days in which Fir's login nodes and filesystem were unusable — their status page
> lists both, ongoing for months, plus GPUs erroring and needing resets. Nibi was close to a
> drop-in: same Slurm account suffixes, same GPU GRES names, same module stack and wheelhouse;
> only paths changed. Dataset 3 is re-downloaded from Synapse directly onto Nibi; Dataset 2 was
> moved from Fir by Globus (`output/globus/README.md` — the one manual step in the experiment).
> Scripts named `hpc_*` are ours and cluster-neutral; `fir_*` files under `inputs/vendor_001/`
> are 001's, vendored byte-identical, and their names are 001's rather than a statement about
> which cluster we use. Background: `notes/cluster_connection_explained.md`.

**Deliverable:** a per-assay translation table between Dataset 2 and Dataset 3 evaluation
space, with enough error characterisation to say honestly whether a CANDI number computed on
Dataset 2 can be placed on the published leaderboard, and with what caveat.

## Design

Four arms, all trained on the **same 312 train+validation EIC experiments**, differing only in
which processing of those experiments they see.

| Arm | Trained on | Scored against | What it is for |
|---|---|---|---|
| **A** | Dataset 3 | Dataset 3 blind truth | Reproduction check against published `Avocado_p0` (MOESM2, `team_id 0`) |
| **B** | Dataset 2 | Dataset 2 blind truth | An internally consistent ENCODE-space leaderboard |
| **C** | Dataset 2 | Dataset 3 blind truth | **A − C** is the total penalty of the processing mismatch |
| **D** | Dataset 2 | Dataset 3 blind truth | C plus a per-assay affine calibration on arcsinh signal, fitted on training experiments only |

`D'` repeats D with 001's per-assay quantile map instead of the affine, as a comparison.
The average-activity baseline is carried in every space, taken from 001's score CSVs.

Only **two** models are trained: B, C and D all score the same Dataset-2-trained model.

## What is reused, and why

`inputs/vendor_001/{fir_score.py,eic_metrics.py,fir_tracks.py}` are **byte-for-byte copies** of
001's scoring implementation (md5s in `inputs/vendor_001/MD5SUMS`). That code reproduced the
published `Avocado_p0` rows to a worst-case relative difference of 2 × 10⁻⁵; re-deriving it
would forfeit that guarantee. Our prediction tracks are written as bigWigs precisely so that
this code runs on them unchanged.

`msevar` is excluded from every comparison: 001 could not reconstruct the organizers' variance
vector. Eight of the nine measures are used.

## Known trap: DNase-seq

Dataset 2's DNase-seq is `read-depth normalized signal`, **not** a −log10 p-value — a different
quantity, not a different pipeline version (001 Result 3). It is kept in *training* (its
per-assay embedding lets the model absorb the scale difference, and it carries real cell-type
information) but is reported separately in arms C and D and excluded from every pooled figure.
See `notebook.md` for the measured consequence.

## Layout

```
scripts/
  01_fetch_inputs.sh      vendor 001's scoring code, bridge, baseline scores, challenge repo
  02_fir_setup.sh         Fir workspace + a torch venv (001's venv has no torch)
  03_fir_bin.sh           both processings onto one 25 bp grid   -> fir_bin_tracks.{py,slurm}
  04_fir_train.sh         two models                             -> avocado.py, fir_train.{py,slurm}
  05_fir_predict.sh       51 blind-test tracks per model         -> fir_predict.py, fir_make_bigwig.py
  06_fir_calibrate.sh     per-assay arcsinh affine               -> fir_fit_affine.py
  07_fir_score.sh         the five scored arms                   -> fir_score.slurm (wrapper only)
  08_translation_table.py the deliverable table
  09_plots.py             figures
output/
  inputs/    vendored code, bridge, baselines, pinned challenge repo
  scores/    one CSV per arm, 51 experiments x 10 bootstraps
  compare/   translation table, reproduction check, per-experiment joins
  figures/   all figures
```

Bulk data (binned matrices, checkpoints, prediction bigWigs) lives on
`/scratch/maxwl/epi_imputation/005/` and is regenerated by `runall.sh`.
