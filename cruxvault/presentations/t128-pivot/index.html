CANDII · lab meeting · exploratory

Can a model re-process a genomics track in a way it never saw? Testing a “pivot” translator

Navigate with → ← or space  ·  n shows the speaker notes

This talk joins two rounds of experiments into one story. Round one tested a new design; round two tested three fixes that the first round suggested.

Every number on the slides is read from the result tables when the deck is built. The study is exploratory, so the slides give readings, not verdicts.

Backgroundwhat a signal track is

The same experiment gives different tracks when you change how its reads are processed

  • A track counts the sequencing reads that land in each 25 bp bin of the genome. Peaks mark where a protein or a histone mark sits.
  • Each processing setting (how many reads, how long, how strict the mapping filter, and so on) changes the counts, but not the biology.

A sequencing experiment produces short reads. A pipeline maps them to the genome and counts how many land in each small bin. The result is a track: a long vector of counts, one per bin.

The pipeline has settings, which we call processing knobs. Fewer reads makes every peak lower and noisier. A stricter mapping filter throws away reads that map to more than one place, so some peaks shrink. The cell and the biology are the same; only the processing differs.

The three small tracks on the right are an illustration, not data.

Backgroundthe task

The task is translation: given a track and its settings, predict the track under other settings

  • Like translating a sentence between languages, but the “languages” are processing settings. The model must learn what each setting does, not memorise examples.
  • Why it matters: public data were processed in many different ways. A translator lets us compare and combine them, and tells us which settings change the signal.

The input is a track X and the settings vector c it was made with. We also give the settings c-prime we want. The model outputs, for every bin, a probability distribution over the count we would see under c-prime: a negative binomial, which is a standard distribution for overdispersed counts.

The settings are a short vector: depth, read length, deduplication, mapping-quality cut, run type, the control settings, and the assay.

Backgroundthe data and the test

We train only on pairs that change one setting from a base track, and test on pairs of settings never seen together

We have seven tracks, one per assay. Each has a base, processed with standard settings, and many arms. Each arm changes exactly one setting of the base: fewer reads, shorter reads, a stricter filter, and so on.

Training sees only base-to-arm and arm-to-base pairs. The real test is arm-to-arm: for example, from a low-depth arm to a strict-filter arm. That pair changes two settings at once, and the model never saw it. We call these never-trained pairs.

One depth arm is held out of training completely, so we can also test a depth level the model never saw.

Problemwhat failed before

The depth test. When two tracks differ only in read depth, the predicted total must scale by the depth ratio. The error is |log2 predicted ratio − log2 true ratio|: 0 is perfect, 1 means off by a factor of 2.

Our earlier model, which we call the direct translator, reads both settings vectors and maps the source straight to the target in one pass. It learns the depth changes it was trained on almost perfectly. On depth changes it never saw, it is several times worse.

But if we take the same trained model and use it twice, first from the arm to the base and then from the base to the other arm, the error drops a lot. Both of those steps are pairs it was trained on. So the knowledge is in the model; its direct answer just does not use it.

Ideabuild the detour into the model

Idea: make every translation go through a shared middle, like a pivot language

Machine translation has an old trick: to go from Finnish to Portuguese with little paired text, translate Finnish to English and English to Portuguese. English is the pivot.

The two-step route does this by hand, with the base track as the pivot. Our new design, the pivot translator, builds it in: one network maps any track into a middle track, and the same network maps the middle track out to any target. If every track can reach the middle and leave it, any pair of settings should work, even a pair never seen together.

Hypothesiswhat we test
Hypothesis
A translator that sends every track through a shared middle, with one network for the way in and the way out, carries its fit over to pairs of settings it never saw together.
Prediction
On never-trained pairs, the pivot translator’s error falls below the direct translator’s, toward the two-step route’s, and its depth error falls toward the trained-pair level.
Against it
The pivot is no better than the direct translator on never-trained pairs: the middle adds nothing.
Boring explanation to rule out
The pivot just copies its input to the middle, so it is a direct translator in disguise.

Exploratory study: no pass bar was set in advance. A gap between two models counts only when it is larger than twice the seed-to-seed spread (method slides).

The prediction is concrete and measurable: lower error on never-trained pairs than the direct translator, approaching the two-step route.

We also name the boring explanation up front. A pivot model could learn to pass its input through the middle unchanged; then it would behave like the direct translator. Several results check for this.

Methodthe building block

Every model has two parts: a small network g reads the settings and tunes a convolutional network f that transforms the track

f is a small one-dimensional convolutional network that slides along the track. It sees a window of about one and a half kilobases around each bin, and it outputs a negative binomial distribution per bin.

g is a small multilayer perceptron. It reads two settings vectors, the "from" settings and the "to" settings, and outputs a scale and a shift for every channel of every layer of f. This is called feature-wise modulation, or FiLM. In plain words: g turns the knobs of f.

The key point: we never train one f per pair. We train g, and g produces the right f for any pair of settings.

We train two versions of g: one g per track, and one g shared across all seven tracks. The main slides show one g per track; the shared version is in the backup.

Methodthe models

The pivot translator runs the same f twice: once into the middle and once out of it

Direct translator: one pass. g reads the source and target settings and sets f; f maps the source to the target. This is our earlier best model.

Two-step via the base: the direct translator used twice, source to base, then base to target. It needs no new training. It is the target we hope the pivot reaches.

Pivot translator: the encoder is f set by g of the source settings and the middle settings. It outputs a middle track Z, one value per bin. The decoder is the same f, with the same weights, set by g of the middle settings and the target settings. Only the settings fed to g differ.

Methodtraining the pivot

The pivot learns from two losses: translate across a trained pair, and translate back to itself

Extra 1: agreement
Push the middles of the two tracks of a pair to be equal, with a weight λ. Both tracks came from one sample, so ideally they share one middle.
Extra 2: noisy middle
Add random noise to the middle during training (a variational autoencoder). The model cannot then hide fine detail of the input in it.

Each training example is a base track and one of its arms. The cross loss encodes the base and decodes it with the arm’s settings, and scores the result against the real arm; and the other way round. The round-trip loss encodes a track and decodes it with its own settings, and scores it against itself.

Both losses are negative log-likelihoods of the observed counts under the predicted distribution.

The two extras are optional, and the first round tested both.

Methodwhat the middle is

The four pivot variants differ only in how tightly the middle is tied to the real base track

Round 1 and 2
Learned pivot
The middle’s settings are learned freely, starting from zero. Nothing says what the middle should be.
Round 1
Boxed pivot
Learned too, but it starts at the base’s settings and must stay inside the range seen in training.
Round 2
Base-labelled pivot
The middle’s settings are fixed to the base’s settings. The middle is told it is the base.
Round 2
Anchored pivot
As base-labelled, and the encoder is also trained to output the real base track. The middle must be the base.

The middle is described by a settings vector, like any track. The variants differ in who chooses it.

From left to right the middle gets closer to the real base track. The anchored pivot is the closest: an extra loss scores the encoder’s output against the actual base track, and the decoder reads that output. That makes it the built-in version of the two-step route.

Methodeverything we ran

Two rounds: round 1 varied the loss, round 2 varied the middle and trained three times longer

modelmiddlelossestraining capruns scored

Round one, with a cap of four thousand training steps, tested the learned pivot under different losses, and the boxed pivot.

Round two, with a cap of twelve thousand steps, kept the learned pivot and added the base-labelled and anchored pivots, and retrained the direct translator under the same cap.

Every model is trained with both versions of g and three random seeds. The no-settings twin is the same model trained with the settings shuffled at random, so it cannot use them; it tells us whether a model uses the settings at all.

Methodhow we score

We score the whole predicted distribution, split its error into shape and scale, and ignore gaps smaller than seed noise

CRPS, lower is better
The distance between the predicted distribution and the observed count, in counts. For a single-number forecast it equals the absolute error.
Shape + scale
Scale error: the part one best rescaling of the prediction removes (a wrong total). Shape error: what is left. Every CRPS is shown with both.
The noise rule
Each model is trained with 3 seeds. A gap counts only if it exceeds 2× the larger seed-to-seed spread; smaller gaps are labelled “within noise”.

Training uses every chromosome except 19, 21 and 22; chromosome 22 picks the best training step; every score is on chromosomes 19 and 21.

CRPS, the continuous ranked probability score, compares a whole predicted distribution with what was observed. Lower is better and zero is a perfect, certain forecast.

We split it in two because the two parts have different causes. A model can get the shape of the track right and the total wrong; one rescaling would fix that. The project rule is to never quote a CRPS without its split.

The noise rule: the seed spread is the largest difference between the three seeds of one model. A gap between two models counts only if it is more than twice the larger of their two spreads.

Different pair groups have different difficulty, because deep targets have large counts and so large errors. So we compare models within one pair group, never a never-trained number against a trained number.

Results(a) round 1 · which loss
Finding 1

Panel a: how far the predicted track moves away from the source track on real pairs, where the settings do change. A model that copies its input scores zero here.

Panel b: the gain over the no-settings twin on never-trained pairs. It is the fraction of the twin’s error that the real model removes. Zero means the settings are ignored.

With only the round-trip loss, the best answer is to copy: encode the track, decode it unchanged, done. The model finds that answer. The noisy middle does not stop it. The cross loss is what forces the model to use the settings. This confirms the boring explanation for this one variant, and rules it out for the others.

Results(b) a sanity check
Finding 2

The swap check gives the model the same settings on both sides. Nothing should change, so a good model returns its input. We measure the typical change as the median of the absolute log ratio of the prediction to the input, over bins with reads.

The pivot models pass it easily, because the round-trip loss trains exactly this. The direct translator never trained on a same-settings pair, and it moves the track several times more.

The second bar shows the pivots are not just copying: on real pairs they move the track much more than in the swap check.

Results(c) the main question · never-trained pairs
Finding 3 · the main result

This is the question of the whole study. Each bar is the error on arm-to-arm pairs that no model saw in training, averaged over pairs, tracks and seeds. The dark part is shape error, the light part scale error. The black ticks are the three seeds.

All three pivot variants have lower bars than the direct translator, and they are ordered: the closer the middle is tied to the real base, the lower the bar. But every one of those gaps is within seed noise. Only the two-step route is clearly better than the direct translator, and it is also clearly better than every pivot.

Note how much of the direct translator’s error is scale error, and how little of the two-step route’s is. The pivots sit in between.

Results(d) where the gap is
Finding 4

The anchored pivot and the two-step route have the same shape: arm, then a prediction of the base, then the target. So we can score each half on its own.

Half one, arm to base, is scored against the real base track. Here the anchored pivot’s encoder is as good as the direct translator’s own arm-to-base map: the gap is within noise.

The full route is not: the two-step route is clearly better. Half one is equal, so the difference must come from half two. In the two-step route, half two is a map trained for exactly that base-to-target pair. In the pivot, it is the same shared network that also does the encoding.

Results(e) round 1 · the loss extras
Finding 5

Round one tried to make the middle a better pivot by changing the loss: agreement between the two middles of a pair at three weights, a noisy middle, and a boxed middle that starts at the base.

None of them moved the never-trained error outside seed noise. That is why round two changed what the middle is, rather than the loss.

Some agreement runs were cancelled before they finished, so those rows have fewer runs; the run count is printed beside each row.

Results(f) round 2 · training longer
Finding 6

In round one most learned-pivot runs were still improving when they hit the step cap. So round two tripled the cap, and kept early stopping: a run stops when its validation score has not improved for four checks in a row.

Each dot is one run’s best step. With room to train, the runs found their best step well before the new cap, and the never-trained error of the learned pivot did not move outside noise. Training time was not the limit.

Results(g) no cost elsewhere
Finding 7

A new design could buy a gain on never-trained pairs by losing on the pairs we already handle. It did not: on trained pairs, scored on held-out chromosomes, and on the held-out depth level, every pivot is within noise of the direct translator.

So the pivot is a safe design; it is just not a better one yet.

Results(h) the depth test
Finding 8

This is the depth test from the problem slide, now for every model. The filled dot is trained depth pairs; the open ring is never-trained depth pairs. A short line means the model carries its depth knowledge over.

Every model fits trained depth pairs. On never-trained depth pairs, the pivots are no better than the direct translator. Only the two-step route comes close to the trained level.

Results(i) is the middle really shared?
Finding 9

Two arms of one track come from the same sample, so a true pivot would map them to the same middle. We measure how far apart their middles are, divided by how far apart the two inputs are. Below one, the middle brings them together. At one or above, the middle keeps the processing differences.

Only the anchored pivot goes below one. The learned pivot’s middle stays almost equal to its input, and its learned settings barely move from where they start. In other words, without an anchor the middle is just the input track, which is the boring explanation from the hypothesis slide.

Discussionwhat we found

Nine findings: the pivot is safe and uses the settings, but it does not yet beat the direct translator where it matters

    Green findings support a part of the design; red findings count against the hypothesis; grey ones are neutral checks.

    Discussionback to the hypothesis

    Reading: the pivot as built does not carry the fit over; the gap sits in the shared decoder

    Ruled out
    Changing the loss (agreement, noise, a box) or training longer. Neither moved the never-trained error.
    Ruled in
    Tying the middle to the real base. The error falls step by step as the tie gets tighter, and the anchored encoder matches the direct translator’s first hop.
    Not shown
    A gain over the direct translator outside noise. Only the two-step route has that, and it decodes with a map trained for each target.

    The ladder orders the routes by how much of the real base track the middle holds. Never-trained error falls along it. Only the last step, to the two-step route, clears the noise, so the order is a reading, not a result.

    The hypothesis said that a shared middle is enough. The readings say the middle has to be the real base, and even then a shared decoder loses to a decoder made for the target.

    Discussioncaveats

    Five things that could change these readings

    Each caveat is a reason to hold the readings loosely. None of them reverses the main result on its own.

    Discussionoptions for the next round

    Four options for the next round; each tests one explanation of the gap

    Option A
    Swap in a target-specific decoder
    Decode the anchored middle with the direct translator’s base-to-target map.
    Teaches whether the shared decoder is the whole gap. Cheap: no new training of the decoder.
    Option B
    A bigger g or a bigger f
    A wider settings network, a deeper convolutional network, or another activation.
    Teaches whether capacity limits the shared decoder. Costs a full grid of runs.
    Option C
    Some arm-to-arm training pairs
    Add a few two-setting pairs to training and test on the rest.
    Teaches whether coverage, not design, is the limit. Real data have few such pairs.
    Option D
    More seeds
    More seeds for the pivots and the shared-across-tracks g.
    Teaches whether the ordered but within-noise gaps are real. Cheap per run.

    These are options, not recommendations. The readings do not rank them.
