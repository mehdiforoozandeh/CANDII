Which processing settings change a track the most?

before/after comparisons: re-processed versions of tracks, each changing one setting, scored for peak height, shape and FRiP.

Navigate with → ← or space  ·  n shows the speaker notes

This is a first, exploratory reading. There are no pass or fail bars. The goal is a ranking of the settings, and an honest list of what still muddies it.

Motivationthe data

Each arm re-processes the same experiment with one setting changed, so base vs arm isolates that setting

Read side
depth · antibody proxy · read length · mapping quality · duplicates · run type
Control side
control scaling · control identity · control depth · fragment extension

The base is the standard single-end ENCODE recipe. Every arm comes from the same raw reads with exactly one setting moved. Read-side settings change which reads enter the pileup, so they change both the counts and the p-values. Control-side settings only change the peak caller's p-values; the counts stay identical to the base.

Motivationthe question

If we change one processing setting, how much does the track move: in the height of its peaks, and in the pattern of where its signal falls?

Why it matters: a model that translates a track across settings should spend its capacity on the settings that matter. The ranking tells us which those are.

Magnitude and shape are kept apart on purpose. A setting can rescale every peak without moving any of them, or leave heights alone and reshuffle the pattern.

Methodthe grid of arms

Ten settings, one or more levels each

Re-run means the whole pipeline was run again from the raw reads. Derived means the change was applied to the base's filtered reads, or only to the peak caller. The two DNase mapping-quality arms came out identical to the base, so they are left out.

Methodwhat we score

Three measures of how far an arm moved from its base

Peak height

Take the base's top 1% of bins (its peaks). Compare the mean signal there, arm over base, on a log2 scale. One unit = peaks doubled or halved.

Shape

One minus the rank correlation between base and arm, on 1 kb bins. Zero = same pattern, whatever the scale. Wider bins damp counting noise.

FRiP

Fraction of reads in peaks: the share of a track's reads in its own top 1% of bins. Counts only. We report arm minus base.

Discussionwhat this reading says

The ends of the ranking are clear; the middle is not yet

Clear

Depth leads peak height. The antibody proxy leads shape. The control-side settings move the p-value track least, control depth weakest of all.

Not resolved

Duplicate removal, run type, read length and mapping-quality filter: on shape they cannot be told apart from re-drawing the reads.

Doubts

Peaks are chosen on the base, so any re-drawn arm reads lower by regression to the mean, and FRiP at low depth is inflated the same way. The DNase FRiP jump is unchecked. Two chromosomes only.

Regression to the mean: the base's top bins are partly top because of the base's own noise, so an independent draw will usually be lower there. A nested depth cut does not suffer this, which is why depth behaves as expected.

Discussionoptions for the next phase

Options for the next phase

Option A

Measure the re-draw floor: score a fresh subsample of the base against the base, and subtract it. Small CPU job; resolves the middle of the ranking.

Option B

Choose peaks on a reference both tracks share (for example their union), to remove regression to the mean from peak height and FRiP. Minutes; cleaner magnitude ranking.

Option C

Check the DNase duplicate-removal jump by hand against the pipeline's own QC. Small; confirms or kills the largest DNase effect.

These are options, not recommendations. Each card says what it costs and what it would teach.
